About ODEYSSEY

A minimalist, full-stack travel planner built with Python (Flask) and vanilla web technologies. Designed with clear logic, genuine mathematical transparency, and a restrained editorial aesthetic.

1. Project Purpose & Vision

Most travel tools suffer from excessive cognitive load: noisy sponsored banners, overwhelming 50-stop whirlwind itineraries, unverified price claims, and confusing AI buzzwords.

ODEYSSEY was conceived as a college mini-project to demonstrate how a minimalist, rule-based expert system can solve real travel planning friction. It respects human pacing (morning, afternoon, and evening slots), provides explicit mathematical cost estimation in Indian Rupees (INR), and pulls live weather data from Open-Meteo.

“Less planning. More exploring.” — Focus on feasible pacing rather than an unrealistic checklist of tourist traps.

Request-Response Lifecycle:

  1. User Input: User defines destination, dates, travelers, INR budget, and interest tags.
  2. Client Validation: Immediate UI checks ensure required fields and positive values before submission.
  3. API Dispatch: POST /api/plan sends sanitized JSON to the Flask backend.
  4. Rule-Based Execution: services.planner evaluates candidates, ranks by interest relevance, distributes across days, and computes itemized expenses.
  5. Weather Enrichment: services.weather contacts Open-Meteo using real coordinates with a 30-minute in-memory cache and offline fallback.
  6. Interactive Presentation: The client renders day-by-day activity cards, updates the budget comparison, and plots geo-markers on the Leaflet map.

3. The Planning & Budget Algorithm

Unlike black-box generative models that invent fictitious locations and fake prices, ODEYSSEY uses a transparent deterministic algorithm:

  • Interest Relevance Scoring: Each candidate activity has tags (nature, history, food, etc.). Activities are scored by the intersection size with the user's selected interests:
    score = (len(activity.tags ∩ user.interests) × 10) + bonus
  • Day & Slot Allocation: Activities are segregated into Morning (9:00 AM–12:30 PM), Afternoon (2:00 PM–5:00 PM), and Evening (6:00 PM–8:30 PM). Maximum 3 primary activities per day to prevent exhaustion.
  • Mathematical Budgeting:
    • Accommodation = ceil(travelers / 2) × daily_hotel_rate × nights
    • Food = travelers × daily_food_allowance × days
    • Local Transit = ceil(travelers / 3) × local_transit_rate × days
    • Activity Admission = travelers × ∑(scheduled_activity_entry_fees)
    • Contingency Buffer = 5% of subtotal

4. College Viva & Presentation FAQ

Q1: Why did you choose Flask and Vanilla JS instead of a heavy React/Node framework?

For a focused mini-project, vanilla JavaScript and Python Flask offer zero build-step overhead, exceptional execution speed, minimal bundle weight, and clear architectural transparency. Any college examiner can inspect the code without dealing with complex node_modules or transpilers.

Q2: How does ODEYSSEY handle offline scenarios or API failures?

Resiliency is built into every layer. If the Open-Meteo external weather API is blocked, offline, or times out, the application intercepts the exception, notes the offline status, and safely presents the full trip plan with seasonal averages. The trip generator never crashes due to an external network glitch.

Q3: How are user trips stored without a relational database?

Version 1 uses browser localStorage (Key-Value store) for instantaneous, zero-latency persistence on the user's device. The data model is structured in standard JSON, making it trivial to attach a SQLite or PostgreSQL database and authentication (like Flask-Login or JWT) in future iterations.

Q4: Are the prices real booking prices?

No. ODEYSSEY explicitly discloses that prices are realistic statistical averages based on current tourism standards in India. It avoids misleading users by pretending to have live hotel reservation integration when none exists.
